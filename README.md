# CargaPronto: сегментация клиентов и прогноз риска задержки доставки

Модель бинарной классификации для логистической компании CargaPronto: прогноз риска задержки заказа с использованием параметров доставки, профиля клиента и результатов географической и поведенческой сегментации.

## Задача

Компания хочет выявлять заказы с высоким риском задержки в момент оформления, чтобы диспетчер мог заранее изменить приоритет сборки, рассмотреть другой способ доставки или уведомить клиента.

Требовалось:

- выделить группы клиентов со схожим поведением и географией;
- проверить, улучшают ли клиентские признаки и сегменты прогноз задержки;
- сравнить логистическую регрессию и CatBoost;
- получить ROC-AUC выше 0,75 на тестовой выборке;
- оценить работу системы предупреждений при пороге вероятности 0,70.

**В терминах машинного обучения:** кластеризация клиентов и бинарная классификация заказов. Целевая переменная — `late_delivery_risk`: 1 означает задержку, 0 — доставку вовремя.

## Данные

Два исходных CSV-файла:

- **ds_s18_customers.csv** — 20 652 клиента, 8 столбцов;
- **ds_s18_orders.csv** — 180 519 заказов, 7 столбцов.

Профиль клиента содержит координаты, сумму и число заказов, среднюю скидку, долю возвратов и давность последнего заказа. Таблица заказов — способ доставки, товарную категорию, время оформления, цену и целевую переменную.

Таблицы объединены по `customer_id`. Пропусков, полных дубликатов и заказов без соответствующего клиента не обнаружено.

Доля задержанных заказов в исходных данных — **54,83%**.

## Стек

Python, pandas, NumPy, scikit-learn, CatBoost, KMeans, StandardScaler, CalibratedClassifierCV, PhiK, t-SNE, Matplotlib, Seaborn

## EDA и предобработка

Из `order_date` созданы признаки месяца, дня недели, часа оформления и выходного дня.

По заданному правилу фильтрации долготы за пределами диапазона `[-125, -20]` исключены **156 клиентов и 1 430 заказов**. После фильтрации осталось **20 496 клиентов и 179 089 заказов**.

Это правило ограничивает географию исследования: за пределами диапазона находятся в том числе реальные клиенты с Гавайев. Поэтому исключённые записи нельзя автоматически считать ошибками геокодирования.

Разделение выполнено через `GroupShuffleSplit` по `customer_id`:

| Выборка | Заказы | Уникальные клиенты |
|---|---:|---:|
| Train | 107 661 | 12 297 |
| Validation | 35 416 | 4 099 |
| Test | 36 012 | 4 100 |

Клиенты между выборками не пересекаются. Масштабирование и кластеризация обучаются только на train-клиентах; для validation и test используются готовые преобразования.

## Сегментация клиентов

Построены два типа сегментов:

- **географические** — KMeans по координатам клиентов после масштабирования, 6 кластеров;
- **поведенческие** — KMeans по `recency`, `total_orders`, `total_sales`, `return_rate` и `avg_discount`, 5 кластеров.

Поведенческая сегментация выделяет группы с высокой долей возвратов, активных клиентов, покупателей со значительными скидками и клиентов с большой давностью последнего заказа.

Число кластеров исследовано с помощью метода локтя, silhouette score и качества последующей классификации. Для визуального анализа поведенческих сегментов использован t-SNE.

## Моделирование

Сравнены четыре набора признаков:

- **A:** только параметры заказа;
- **B:** параметры заказа и клиентские признаки;
- **C:** параметры заказа, клиентские признаки и метки кластеров;
- **D:** параметры заказа и метки кластеров без исходных клиентских признаков.

Результаты сравнительного эксперимента на validation:

| Набор | LogisticRegression, ROC-AUC | CatBoost, ROC-AUC |
|---|---:|---:|
| A. Базовые признаки | 0,7273 | 0,8017 |
| B. Базовые + клиентские | 0,7460 | **0,8113** |
| C. Базовые + клиентские + кластеры | **0,7462** | 0,8112 |
| D. Базовые + кластеры | 0,7317 | 0,7990 |

Клиентские признаки повысили ROC-AUC CatBoost на **0,96 процентного пункта**. Добавление кластеров поверх этих признаков практически не изменило качество.

Финальная конфигурация — отдельно обученный CatBoost на наборе C. Результаты сравнительного эксперимента выше не следует смешивать с метриками этой финальной модели.

## Подбор числа кластеров

Проверены 16 комбинаций:

- `k_geo`: 4, 8, 12, 20;
- `k_rfm`: 6, 12, 20, 30.

В сохранённом эксперименте лучший ROC-AUC на validation — **0,8079** при `k_geo=4`, `k_rfm=6`. Диапазон результатов — **0,7743–0,8079**.

В финальной модели сохранена конфигурация **6 географических и 5 поведенческих кластеров**. Она не является победителем этого перебора: эксперимент с числом кластеров рассматривается отдельно от финальной конфигурации.

## Калибровка вероятностей

До калибровки модель не выдавала предупреждений при пороге 0,70, несмотря на ROC-AUC выше целевого уровня. Хорошее ранжирование заказов не гарантирует корректную шкалу вероятностей.

Для применения заданного порога использована **изотоническая калибровка** на validation-выборке.

После калибровки модель выдала **12 437 предупреждений** на тесте — примерно для **34,54% заказов**.

## Анализ важности признаков

Встроенная важность CatBoost:

| Признак | Важность |
|---|---:|
| `shipping_mode` | 63,68% |
| `order_hour` | 16,79% |
| `return_rate` | 15,64% |
| `order_weekday` | 1,17% |
| `geo_cluster` | 0,94% |
| `behav_cluster` | 0,87% |

Основной сигнал связан со способом доставки, временем оформления и долей возвратов клиента.

Кластерные признаки имеют небольшой вклад в прогноз. Их основная потенциальная польза — интерпретация клиентской базы и подготовка разных стратегий обслуживания. Важность признаков отражает закономерности модели, а не доказывает причины задержек.

## Результат

**Финальная модель — CatBoost с изотонической калибровкой и порогом предупреждения 0,70.**

На отложенной тестовой выборке:

| Метрика | Значение |
|---|---:|
| ROC-AUC после калибровки | **0,7769** |
| Precision | **87,90%** |
| Recall | **55,85%** |
| F1 | **0,6830** |
| TP | 10 932 |
| FP | 1 505 |
| FN | 8 643 |
| TN | 14 932 |

Целевое требование **ROC-AUC > 0,75 выполнено**.

Около 88% предупреждений соответствуют реальным задержкам, однако модель пропускает около 44% задержанных заказов. Это система приоритизации риска, а не гарантия своевременной доставки.

## Что было самым сложным

Главная сложность — совместить сегментацию клиентов и оценку риска заказа без пересечения клиентов между выборками. Масштабирование и KMeans обучаются на уникальных train-клиентах, после чего сегменты присваиваются клиентам validation и test.

Второй момент — отделить качество ранжирования от качества вероятностей. Модель преодолела целевой ROC-AUC, но до калибровки не работала при заданном пороге 0,70.

Третий — проверить пользу кластеризации, а не предполагать её заранее. Эксперименты показали, что исходные клиентские признаки помогают прогнозу, а их замена сегментами приводит к потере информации.

## Ограничения

- Разделение по клиентам проверяет перенос на других клиентов, но не заменяет хронологическую проверку на будущих заказах.
- Клиентские агрегаты предоставлены готовыми. Их доступность на момент каждого исторического заказа не подтверждена; для внедрения нужны признаки, рассчитанные строго по прошлой истории.
- Validation используется и для выбора моделей, и для калибровки. Для дальнейшей проверки желательно выделить отдельную калибровочную выборку.
- Географический фильтр исключает часть реальных регионов, поэтому качество на этих клиентах не оценивалось.
- Кластеризация почти не повышает качество относительно исходных клиентских признаков.
- Снижение задержек и штрафов не измерялось в реальном пилоте. Для оценки эффекта нужны операционные данные и контролируемый эксперимент.
